<objective>
Establish the backend foundation for v2.3 door integration: a new Devices module with `IDoorController`/`IDeviceUnlockKeyProvider`/`IDeviceConnectionCryptoService` abstractions, an in-process `SimulatedDoorController` driven by a thread-safe `DoorSimulatorState`, two persistence tables (`devices`, `DeviceUnlockAudit`) with append-only triggers, the security bar (HMAC-SHA256 signature, nonce + timestamp replay window, per-device rate limit, porteiro role, tenant opt-in flag), and the integration-test suite that proves the security bar works against the simulator. Phase 23 ships zero UI surface — only the API service + DTO interfaces in Angular, ready for Phases 24/26 to consume.

Purpose: DOOR-01/02/03/04/07/15. Everything else (admin UI, reader events, health monitoring) is later phases. The reason 23 ships backend-first: the simulator harness is what every later phase's integration suite re-uses to prove their surface doesn't regress the security bar — getting the simulator right is the foundation. The integration tests cover the full security bar so that when Phase 25 adds event ingestion on top of the same `DeviceEvent` pipeline, the unlock path stays regression-safe.

    - `DoorUnlockOutcome` enum: Success, DeviceOffline, AuthFailed, RateLimited, UnknownTenantFlag, UnknownDevice, DeviceInactive.
    - `DeviceErrors` static class — strongly-typed exceptions / `Result.Failure` factories: `DeviceNotFound`, `DeviceInactive`, `TenantDoorIntegrationDisabled`, `InsufficientRole`, `ReplayWindowExceeded`, `SignatureInvalid`, `RateLimitExceeded`. Each carries the matching ProblemDetails `type` URI (e.g., `https://errors.controleasy.app/devices/unlock-rate-limited`).

    **Application layer:**
    - `IDoorController.UnlockAsync(Guid tenantId, Guid deviceId, DoorUnlockCommand command, CancellationToken ct) → Task<DoorUnlockResult>` where `DoorUnlockResult` is a discriminated type with `Outcome`, `CorrelationId`, `OccurredAtUtc`. `DoorUnlockCommand` carries `Nonce`, `TimestampUtc`, `SignatureBase64Url`, `BodyHashHex`, `ActorProfileId`.
    - `IDeviceUnlockKeyProvider.GetKeyForAsync(Guid tenantId, CancellationToken ct) → Task<byte[]>` returning the per-tenant HMAC-SHA256 key. Implementation uses HKDF-SHA256 over the existing tenant master seed with `KeyDerivationPurpose.DOOR_UNLOCK_V1`. Reuses the existing `ITenantMasterKeyProvider` from BuildingBlocks — do NOT introduce a parallel key-management scheme.
    - `IDeviceConnectionCryptoService.Encrypt(Guid tenantId, ReadOnlySpan<byte> plaintext) → byte[]` / `Decrypt(Guid tenantId, ReadOnlySpan<byte> ciphertext) → byte[]`. Implementation uses .NET `AesGcm` (96-bit IV, 128-bit tag, 32-byte key). Per-tenant key derived via HKDF with `KeyDerivationPurpose.DOOR_CONNECTION_PARAMS_V1`. Ciphertext format: `version(1) || iv(12) || tag(16) || ciphertext(N)`. Constant-time comparison everywhere; never log the plaintext or the key.
    - `IDeviceRepository` — `Linq<Devices>`-based: `GetByIdAsync(tenantId, deviceId)`, `ListAsync(tenantId, isActive)`, `InsertAsync(device)`. Uses `ITenantAwareLinqFactory` so every read is tenant-scoped.
    - `IDeviceUnlockAuditRepository.InsertAsync(audit)` — append-only insert. No Update/Delete methods exist on the abstraction (the absence is intentional and matches the DB trigger).
    - `IDeviceNonceCache` — `TryConsumeAsync(tenantId, deviceId, nonce, ttl) → bool`. Backing: `ConcurrentDictionary<string, DateTimeOffset>` keyed by `$"{tenantId}:{deviceId}:{nonce}"`. Singleton, FIFO eviction via a 60-second ticker.
    - `IDeviceUnlockRateLimiter` — `TryAcquireAsync(tenantId, deviceId) → bool`. Backing: `ConcurrentDictionary<string, DateTimeOffset>`. Last-write-wins; entry is the timestamp of the most recent allowed unlock. A subsequent attempt within `RATE_LIMIT_WINDOW_SECONDS` (3) returns false.
    - `IDoorSimulatorState` — exposes `RecordAttempt(tenantId, deviceId, outcome)`, `GetAttempts(tenantId, deviceId) → IReadOnlyList<SimulatedAttempt>`, `SetFailureMode(deviceId, mode)` (test-only), `SetOffline(deviceId, until)` (test-only). Production never calls Set methods; the dev-only inspector endpoint guards them with `IWebHostEnvironment.IsDevelopment()`.
    - `DoorUnlockRequest` / `DoorUnlockResponse` — DTOs matching the API contract. The request includes `nonce`, `timestampUtc`, `signatureBase64Url`; the response includes `outcome`, `occurredAtUtc`, `correlationId`.
    - `UnlockDeviceHandler` (NOT MediatR; registered as scoped service) — the heart of the security machinery. Pseudocode flow:
      ```
      1. if (tenant.DoorIntegrationEnabled == false) return DoorUnlockResult.UnknownTenantFlag;
      2. var key = await keyProvider.GetKeyForAsync(tenantId);
      3. var expected = ComputeHmacSha256(key, canonicalize(deviceId, request));
      4. if (!ConstantTimeEquals(expected, request.SignatureBase64Url)) return DoorUnlockResult.AuthFailed;
      5. if (Math.Abs((now - request.TimestampUtc).TotalSeconds) > REPLAY_WINDOW_SECONDS) return DoorUnlockResult.AuthFailed;
      6. if (!await nonceCache.TryConsumeAsync(tenantId, deviceId, request.Nonce, ttl=5min)) return DoorUnlockResult.AuthFailed;
      7. if (!await rateLimiter.TryAcquireAsync(tenantId, deviceId)) {
            auditRepo.Insert(new DeviceUnlockAudit(... outcome: RateLimited ...));
            return DoorUnlockResult.RateLimited;
         }
      8. var device = await deviceRepo.GetByIdAsync(tenantId, deviceId);

      10. var audit = new DeviceUnlockAudit(... outcome: simResult.Outcome ...);
          auditRepo.Insert(audit);
          logger.LogInformation("device.unlock {TenantId} {DeviceId} {Outcome} {CorrelationId}", ...);
      11. return simResult;
      ```
