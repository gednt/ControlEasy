# Requirements: ControlEasy Reborn — Milestone v2.2

**Defined:** 2026-09-22 (party-mode planning session, autonomous)
**Shipped:** 2026-09-26
**Core Value:** Gatehouse staff can reliably register and control access through a fast, tenant-isolated web UI.

## v2.2 Requirements (Final Outcomes)

Software-only closeout: finish the ledger, complete pending UI surfaces, advance mockup parity. Derived from `.planning/milestones/v2.1-MILESTONE-AUDIT.md` carryovers, v2.0/v2.1 partial requirements, and `.specs/` work in progress.

### Ledger & Reports Polish

- [x] **LEDGER-01**: Daily visit-count summary matches the unified ledger at the tenant day boundary (INFRA-02 closeout — `GetVisitCountsByDayAsync` bucketed via TenantDayBoundary, not raw UTC) — **Phase 19, Plan 19-01**
- [x] **LEDGER-02**: Ledger status filter offers only statuses the backend can return; selecting any option returns real rows or a correct empty state (no inert 'Recorded'/'Refused' options) — **Phase 19, Plan 19-02**
- [x] **LEDGER-03**: Ledger search scope is honest — placeholder promises only what backend `q` covers (PackageDescription/SubjectName/Purpose) or backend scope is extended to match the promise — **Phase 19, Plan 19-02**
- [x] **LEDGER-04**: Package-drop UI can register condominium-level drops (DestinationApartmentId omitted), not only apartment-bound ones (VISIT-06/07 capability surfaced) — **Phase 19, Plan 19-03**
- [x] **LEDGER-05**: `X-Total-Count` header exposed via `WithExposedHeaders` so pagination works for non-same-origin consumers (v2.0 tech-debt shim closeout) — **Phase 19, Plan 19-04**

### Account Operations UI

- [x] **ACCNT-01**: TenantAdmin can reset another admin's or porteiro's password from the condominium management UI (PASS-03 closeout — UI caller behind TenantAdmin-reachable guard, not platformAdmin-only) — **Phase 20, Plan 20-01/20-02**
- [x] **ACCNT-02**: Reset flow shows delivery feedback (temp password dispatched via SMTP) and enforces `MustChangePassword` on next login — **Phase 20, Plan 20-01/20-02**

### Consent Audit UI

- [x] **CONSU-01**: Consent audit review UI: filter by date range, category, entry state, porteiro (CONSENT-03 closeout) — **Phase 20, Plan 20-03**
- [x] **CONSU-02**: Audit rows render state-appropriate evidence — `entered_with_consent` photo thumbnail with lightbox, `entered_override` highlighted with reason + porteiro, `gatehouse_only`/`denied` badges — **Phase 20, Plan 20-04**
- [x] **CONSU-03**: Consent audit CSV export with millisecond-precision `recorded_at` — **Phase 20, Plan 20-04** (verified no-rebuild)

### Photo Capture UI

- [x] **PCAP-01**: `ce-photo-capture` component: camera mode (`getUserMedia`) and file-picker mode with client-side compression ladder (≤1280px, 0.8→0.6→0.3) and EXIF strip via canvas redraw (implements `.specs/photo-capture/` PHOTO-02; renamed PCAP to avoid colliding with validated v2.0 PHOTO-01 storage requirement) — **Phase 21** (regression-green; existing suites)
- [x] **PCAP-02**: Photo display: thumbnails in record lists (lazy), source in detail view, click-to-enlarge lightbox, integrated into resident/visitor/vehicle/service-provider record pages — **Phase 21, Plan 21-01/21-02**
- [x] **PCAP-03**: Upload resilience: 3 attempts with 1s/2s/4s backoff, clear error states for camera-denied, file-too-large, and retries-exhausted — **Phase 21** (regression-green; existing suites)
