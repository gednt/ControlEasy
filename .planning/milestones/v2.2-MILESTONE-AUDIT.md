## Cross-Phase Integration

The integration checker subagent was **not spawned** per the user's "Do NOT execute code" instruction. The following integration observations come from reading the per-phase VERIFICATION.md files and git history.

1. **ProfileId key-space (CONSU-01 ↔ CONSU-02 ↔ ACCNT-01/02).** `StaffMemberResponse.ProfileId` (= `AttendantProfile.Id`) is the shared key space across the staff list, the consent audit row name resolution, and the consent audit porteiro filter. Keying on `User.Id` would silently miss every row. Enforced in Plan 20-04 (audit row name map) and Plan 20-03 (porteiro dropdown) — both project from the same `GET /api/v1/security/staff`. No evidence of mismatch in VERIFICATION.md.

2. **Cleanup-branch prerequisite (already on `main`).** Per v2.2-ROADMAP.md sequencing note, Phases 19–22 depend on `feat/unified-visits-flow-cleanup` (`2979bec`) and `fix/gatehouse-direction-persistence` (`0fdee5a`) being on `main`. Both merged: PR #11 (`7a5eb35`) and PR #10 (`0d8f96a`). Recorded as prerequisite in commit `cc5f551`. No ledger/consent-audit work in v2.2 duplicates those merges.

3. **Phase 19 CORS deviation (forced by stack).** `19-VERIFICATION.md` documents a plan-vs-implementation deviation: plan prescribed endpoint-level `WithExposedHeaders`, which doesn't exist in ASP.NET Core 8.0 SDK. Phase 19 used policy-level `.WithExposedHeaders("X-Total-Count")` instead — identical end-result, no exposure-surface widening. Documented and accepted.

4. **Phase 21 list-endpoint 400 contract change.** `[FromQuery] entityType` / `entityId` were made nullable in `PhotosEndpoints.cs` so the in-handler `BadRequest` guard is reachable (otherwise framework returns 500). Phase 21 VERIFICATION.md flags this as a real API contract change visible to hand-rolled clients; no such clients exist in the repo.

5. **Phase 22 OpenAPI client drift.** Phase 22 reports zero content diff after stage 6 OpenAPI drift check; Phase 21 regenerated `api-v-1-photos-get.ts` and `photos.service.ts` once after the nullable-photos-params change.
