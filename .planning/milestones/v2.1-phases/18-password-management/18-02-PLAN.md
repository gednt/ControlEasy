# Plan 18-02: Administrative Password Reset Endpoints & Token Revocation

## Objective
Implement administrative password reset capabilities for Platform Admins and Tenant Admins:
1. `POST /api/v1/security/users/{userId}/reset-password`:
   - Platform Admin can reset any user across tenants; audit-logged.
   - Tenant Admin can reset their own gatekeepers/attendants only (scoped to their own tenant); cross-tenant attempts receive 403 Forbidden.
2. Atomically issue a temporary password, re-arm `MustChangePassword = true`, and persist the hashed temp password in `PasswordResetRequests`.
3. Revoke all active refresh tokens for the user (`RevokeAllForUserAsync`).
4. Prevent temp password leakage in logs via redaction architecture test.

## Requirements Covered
- **PASS-02**: Platform admin can reset any user's password from the condominium management page — generates a one-time temp password, re-arms `MustChangePassword`, revokes the user's refresh tokens, audit-logged; cross-tenant attempts get 403 (not 404)
- **PASS-03**: Tenant admin can reset their own gatekeepers' passwords — same temp-password + `MustChangePassword` + revocation semantics, scoped to own tenant
- **PASS-04**: Delivery safety — hashed temp password + delivery state persisted in same transaction; temp passwords never logged (redaction arch test); accounts never locked out in response to reset floods

## Tasks

### Task 1: Refresh Token Revocation Seam
- Location: `src/Modules/Security/ControlEasyReborn.Modules.Security.Application/Abstractions/IRefreshTokenRepository.cs` and `RefreshTokenRepository.cs`
- Add `Task RevokeAllForUserAsync(Guid userId, CancellationToken ct);`.
- Query: `UPDATE RefreshTokens SET RevokedAtUtc = UTC_TIMESTAMP() WHERE UserId = @UserId AND RevokedAtUtc IS NULL;`.

### Task 2: Reset Password Command & Handler
- Location: `src/Modules/Security/ControlEasyReborn.Modules.Security.Application/Handlers/ResetUserPasswordHandler.cs`
- Validate permissions:
  - If caller is `PlatformAdmin`: allowed for any target user.
  - If caller is `TenantAdmin`: target user must belong to caller's `TenantId` AND have role `Porteiro` / gatekeeper. If user belongs to a different tenant, return 403 Forbidden (`ForbiddenException` / RFC 7807 403, NOT 404).
- Generate unambiguous temporary password via `ITempPasswordGenerator`.
- Hash temp password with `IPasswordHasher` (work factor 11).
- In a single transaction:
  - Update user's password hash and set `MustChangePassword = true`.
  - Persist `PasswordResetRequest` row with `DeliveryState = Sent` (or delivered to caller/email).
- Call `_refreshTokenRepository.RevokeAllForUserAsync(userId)`.
- Emit structured audit log without logging the cleartext password (log userId, tenantId, initiatedBy, timestamp).
- Return temp password to the admin caller in response DTO (`ResetUserPasswordResponse(string TempPassword)`).

### Task 3: API Endpoint Registration
- Location: `src/Modules/Security/ControlEasyReborn.Modules.Security.Api/Endpoints/SecurityEndpoints.cs`
- Register `POST /api/v1/security/users/{userId}/reset-password`.
- Require authorization: `RequireAuthorization(Policies.AdminOrTenantAdmin)`.

### Task 4: Architectural Redaction Test
- Location: `tests/ControlEasyReborn.ArchitectureTests/SecurityRedactionTests.cs`
- NetArchTest rule ensuring handlers, commands, or logging calls never expose `TempPassword` or `Password` in unredacted log message templates.

### Task 5: Integration Tests
- Location: `tests/ControlEasyReborn.IntegrationTests/Security/PasswordResetTests.cs`
- Platform Admin resets a Tenant Admin password -> succeeds, temp password works, `MustChangePassword` is true, old refresh tokens rejected.
- Tenant Admin resets a Porteiro password -> succeeds.
- Tenant Admin attempts to reset a user in another tenant -> receives 403 Forbidden.
