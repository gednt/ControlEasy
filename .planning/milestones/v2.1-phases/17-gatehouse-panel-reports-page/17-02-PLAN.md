# Plan 17-02: QR Scanner Camera Orientation Persistence

## Objective
Enable the QR scanner to remember camera direction (facingMode: `environment` vs `user`) in browser `localStorage` per device. When reopening the scanner, it must initialize in the stored orientation, toggle properly upon clicking the flip button, apply corresponding video mirroring, and gracefully handle fallback if constraints are overconstrained.

## Requirements Covered
- **PANEL-03**: QR scan screen remembers camera direction (facingMode) in browser localStorage per device, reopening in the last-used orientation at each gate

## Tasks

### Task 1: Camera FacingMode State & LocalStorage Persistence
- Location: `src/Web/ControlEasyReborn.Web/src/app/features/access-control/qr-scan.page.ts`
- Define localStorage key constant: `const CAMERA_FACING_MODE_STORAGE_KEY = 'ce_qr_facing_mode';`
- Allowed values: `'environment'` | `'user'`.
- On initialization:
  - Read persisted value from `localStorage.getItem(CAMERA_FACING_MODE_STORAGE_KEY)`.
  - If null/invalid, default to `'environment'` on mobile devices / tablets or fallback to `'user'`.
  - Initialize `facingMode` signal and `isMirrored` signal (`true` if `facingMode === 'user'`, `false` if `facingMode === 'environment'`).
- In `startScanner()`:
  - Pass constraints with `{ video: { facingMode: currentFacingMode } }` to `decodeFromConstraints` (or `decodeFromVideoDevice` with appropriate device resolution / constraints).
  - Provide fallback to default device if overconstrained error (`OverconstrainedError`) occurs.
- In `toggleMirror()` / `flipCamera()`:
  - Toggle `facingMode` between `'environment'` and `'user'`.
  - Persist the new choice in `localStorage`.
  - Update `isMirrored` signal.
  - Restart scanner with the new constraints so the actual camera switches.

### Task 2: Unit Tests
- Location: `src/Web/ControlEasyReborn.Web/src/app/features/access-control/qr-scan.page.spec.ts`
- Assert that `localStorage` is checked upon init and stored orientation is respected.
- Assert that toggling the camera updates `localStorage` and triggers scanner restart with updated constraints.
- Assert that overconstrained errors fallback gracefully.
