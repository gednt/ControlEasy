## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gatehouse client → POST /api/v1/access-events/scans | Untrusted VisitorName/VisitorDocument fields on the scan request cross into the Visits table |
| JWT tenant claim → Visits/AccessEvents writes | Tenant isolation must hold for the new create/check-in writes |
| Operator identity → AttendantProfileId/GatehouseId stamping | ProfileId comes from the JWT, must not be client-suppliable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-01-01 | Tampering | VisitorName/VisitorDocument on RecordAccessScanRequest | medium | mitigate | Values are stored as gatehouse-entered operational data only — never used for authz decisions; length-constrain via FluentValidation (VisitorName ≤ 200, VisitorDocument ≤ 20 mirroring Visits schema) and reject oversized payloads with ProblemDetails |
| T-16-01-02 | Info disclosure (cross-tenant) | VisitorArrivalHandler reads/writes | high | mitigate | All queries via ITenantAwareLinqFactory tenant-scoped where clauses; integration test asserts a second tenant's visitor document never matches another tenant's visit |
| T-16-01-03 | Repudiation | Visit create/check-in actions | low | accept | AttendantProfileId/GatehouseId stamped from JWT claims server-side; Serilog structured logging already carries tenant/subject context per established pattern |
| T-16-01-04 | Elevation of privilege | VisitStatus transitions via crafted payloads | low | accept | State machine enforced in the Visit domain entity (CheckIn only from Pending, CheckOut only from CheckedIn); handler cannot bypass it since Visit constructors/mutations are private-set |
| T-16-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager installs in this plan — NuGet/npm dependency set unchanged; gate not triggered |
