<objective>
Expose the `X-Total-Count` pagination header to non-same-origin consumers (LEDGER-05).

Purpose: `GET /api/v1/reports/history` already sets `X-Total-Count` on the response
(`ReportEndpoints.cs` line 49), but the endpoint never calls `WithExposedHeaders(...)`, and the
`AngularDev` CORS policy uses `AllowAnyHeader()` (which governs request headers only, not response
header exposure). Consequently browser JS in a genuine cross-origin deployment silently reads
`null` from `res.headers.get('X-Total-Count')` and falls back to `res.body.length`, capping the
pagination total at the page size (RESEARCH Pitfall 3).

Output: `WithExposedHeaders("X-Total-Count")` on the `/history` endpoint, plus an integration
assertion proving the header is exposed cross-origin.
</objective>

Per LEDGER-05: in `ReportEndpoints.cs`, the `/history` `MapGet` chain (lines 29-52) returns
`Results.Ok(rows)` after setting `httpContext.Response.Headers["X-Total-Count"] = total.ToString();`
but never exposes the header to cross-origin consumers. Append
`.WithExposedHeaders("X-Total-Count")` to the `/history` MapGet fluent chain — directly after the
existing `.Produces<IReadOnlyList<HistoryRowResponse>>(StatusCodes.Status200OK)` call — so ASP.NET
Core emits the `Access-Control-Expose-Headers` metadata for that endpoint.

This is the localized, canonical fix (RESEARCH Open Question 4): it applies regardless of which CORS
policy is active and satisfies the success criterion "non-same-origin consumers receive the header."
Do NOT modify the CORS policy in `Program.cs` (the `AngularDev` policy's `AllowAnyHeader()` remains
request-header-only, which is correct); the endpoint-level exposure is sufficient and avoids widening
header exposure for all endpoints. Do NOT touch the `visit-counts-by-day` or `residents-per-apartment`
endpoints — only `/history` carries `X-Total-Count`.

The `Microsoft.AspNetCore.Builder` namespace is already imported (`using Microsoft.AspNetCore.Builder;`
at the top of the file), which provides the `WithExposedHeaders` minimal-API extension; no new using
is required.
