<objective>
Make Phase 23's device foundation administratable: a TenantAdmin flips the `DoorIntegrationEnabled` flag on their condominium, then registers/edits/activates-deactivates/removes devices via the existing `/administration` page. Cross-tenant isolation is enforced end-to-end. The Angular UI is design-system conformant (no new components invented) and the modal enforces "connection params entered once, never shown again" by server contract.

Purpose: DOOR-05 + DOOR-06. The reason 24 ships after 23: every mutation in 24 depends on Phase 23's encryption service (used by RegisterDeviceHandler) and the Phase 23 `Device` entity's `IsActive` flag (used by Phase 23's UnlockDeviceHandler for the "deactivated/removed device immediately rejects unlock" requirement). Building 24 before 23 would mean rewriting 23's entity, which is a forbidden plan-revision. After 24 ships, Phase 25 builds the event-ingestion pipeline on the same `Device` entity (no entity mutation needed in 25).

Output: 5 new C# handlers + 3 new validators + 5 new DTOs + 1 new endpoint class (`TenantEndpoints`) + ~10 new repository/abstraction files + 1 new Angular modal component + 2 new spec files + 1 new admin-page spec extension + 2 new SQL migration lines + 2 new integration test files. The page itself gets one new `<section>` block (no new route, no new guard).

</objective>

    **Application handlers (all NOT MediatR; registered as scoped services):**

    - `ToggleDoorIntegrationHandler` — `(tenantId, enabled, actorProfileId, correlationId)` → updates flag + writes the two audit columns + structured log `tenant.door_integration.{enabled|disabled}`. Does NOT require the flag itself to be enabled (bootstrap case).
    - `RegisterDeviceHandler` — `(tenantId, request, actorProfileId)` → validates request shape, looks up `gatehouseId` via `IGatehouseLookup.GetGatehouseTenantAsync(gatehouseId)` returning the gatehouse's tenantId — if it differs from the actor's tenantId, throw `DeviceErrors.GatehouseNotFound` (404, NOT a cross-tenant leak). Encrypts via `IDeviceConnectionCryptoService`. Inserts a new `Device`. Returns `DeviceDetail` with `connectionParams` redacted (`{redacted:true,last4:"abcd"}`).
    - `EditDeviceHandler` — `(tenantId, deviceId, request, actorProfileId)` → loads device (tenant-scoped). For each optional field in the request, applies the change. If `connectionParams` is present, rotates the ciphertext atomically.
    - `ActivateDeactivateDeviceHandler` — `(tenantId, deviceId, isActive, actorProfileId)` → updates `IsActive`. If `isActive=false`, ALSO sets `RemovedAtUtc=now` (semantic: deactivation IS soft-delete). Wait — see the design decision below.
    - `RemoveDeviceHandler` — `(tenantId, deviceId, actorProfileId)` → checks for recent `DeviceUnlockAudit` rows in the last 24h; if present, throws `DeviceErrors.RemoveBlockedByRecentActivity` (409 Conflict with `title="device-remove-recent-activity"` and a `detail` pointing to the audit page). Otherwise sets `IsActive=false` and `RemovedAtUtc=now`. Soft-delete, not hard-delete.

    **Design clarification on IsActive vs RemovedAtUtc:** The two are linked — `IsActive=false` ⇒ `RemovedAtUtc IS NOT NULL`. The list endpoint excludes rows where `RemovedAtUtc IS NOT NULL` AND treats `IsActive=false` rows as "not in the list". Set both at once in both handlers.

    **Validators:** `RegisterDeviceValidator` validates `deviceType ∈ {"reader","controller"}`, `vendor` non-empty ≤ 64 chars, `gatehouseId` is a valid UUID, `connectionParams` is parseable JSON. `EditDeviceValidator` mirrors with all fields optional.

    **DTOs:** `RegisterDeviceRequest`, `EditDeviceRequest`, `DeviceDetail`, `DeviceListItem`, `ToggleDoorIntegrationRequest` — shape per CONTEXT.md.

    **Abstractions:** `IGatehouseLookup` (single method `GetGatehouseTenantAsync(gatehouseId) → Task<Guid?>` returning the gatehouse's tenantId or null); `ITenantDoorIntegrationRepository` (read+write the flag + the audit columns).

    **Permissions:** Add `Devices.Read`, `Devices.Write`, `Tenants.ToggleDoorIntegration` to `DevicePermissions`. The existing `Devices.Unlock` from Phase 23 stays.
