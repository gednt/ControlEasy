<objective>
Wire a lazy thumbnail column into the residents, vehicles, visits, and service-providers list tables using the `ce-photo-thumb` primitive from plan 21-01.

Purpose: This is the direct closeout of PCAP-02's unmet clause. RESEARCH verified that lightbox, source-in-detail, and 4-page panel integration are all already shipped, but no list table renders a thumbnail column — the lists show an avatar/plate/name only. </objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01 | Information Disclosure / Elevation | list thumbnail column (`ce-photo-thumb`) | mitigate | Delegates to `PhotosApiService` (bearer-carrying HttpClient) and the tenant-scoped `ITenantAwareLinqFactory` list path; no raw photo URLs. Cross-tenant list isolation verified by integration test in plan 21-03. |
| T-21-02 | Spoofing | thumbnail render (`ce-photo`) | mitigate | Thumbnails render via the authenticated `photosApi.get(id)` → objectURL path inside `ce-photo`, never a plain `<img src="/api/v1/photos/...">`. |
| T-21-04 | DoS (eager fetch of N source blobs) | list thumbnail column | mitigate | `ce-photo-thumb`/`ce-photo` use IntersectionObserver fetch-laziness — off-screen rows issue zero blob fetches (plan 21-01). |
| T-21-06 | Information Disclosure (wrong entity type literal) | page wiring | mitigate | `entityType` literals are statically bound to `resident`/`visitor`/`vehicle`/`service-provider` (exact `PhotoEntityType` union values) so a row can only request photos of its own entity; backend rejects unknown types via the validator. |
| T-21-SC | Tampering (supply chain) | npm/pip/cargo installs | accept | No new packages this phase; `exifr` devDependency already verified (registry OK). |
