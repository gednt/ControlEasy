<objective>
Build the lazy-thumbnail primitive that Phase 21's one remaining gap depends on: a fetch-lazy `ce-photo` and a thin `ce-photo-thumb` wrapper that resolves an entity to its most-recent photo id.

Purpose: PCAP-02's first clause — "thumbnails in record lists (lazy)" — is the single unmet requirement in this gap-closeout phase. No list table renders a thumbnail column today, and `ce-photo` fetches the full source blob eagerly (the browser `loading="lazy"` attribute on the inner `<img>` only defers decode, not the authenticated HTTP fetch). This plan delivers the reusable primitive that later plans (21-02) wire into the four record lists. It does NOT rebuild capture/compression/retry (PCAP-01/PCAP-03 are already shipped and tested — see RESEARCH.md).

Output: fetch-lazy `CePhotoComponent` (new `lazy` input + IntersectionObserver gate, default off so gallery/panel/lightbox are regression-safe) and `CePhotoThumbComponent` (lazy entity→photo-id resolver that delegates the blob fetch to `ce-photo`), both unit-tested and exported from the design-system barrel.

**Plan decision (surfaced, not silently picked — RESEARCH Assumption A3):** "lazy" in PCAP-02 is interpreted as **true fetch-laziness** — defer the authenticated `GET /api/v1/photos/{id}` blob request until the row nears the viewport — not merely the browser decode hint. This is the honest reading of PCAP-02 and avoids the ~99%-bandwidth-waste of eagerly fetching full source blobs for every list row. The IntersectionObserver gate lives in `ce-photo` (the recommended approach per RESEARCH). If the product owner later accepts decode-lazy-only, the gap shrinks to removing the `lazy` gate and keeping the column — flagged in the phase return message, not resolved here.
</objective>

Provide a fake global `IntersectionObserver` in the spec's `beforeEach` (a class whose `observe` records the target and exposes a `triggerIntersect()` helper so tests can fire the callback deterministically).
